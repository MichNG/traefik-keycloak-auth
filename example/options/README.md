# Configuration examples, option by option

Every option of the plugin (see the "Options" table of the [root README](../../README.md))
has a runnable example here, with every variant of it. Each file is a complete
Traefik **dynamic** configuration (a middleware plus a router) that is loaded by a
real Traefik in the `make options` check (`docker/e2e-options.sh`), which asserts
that the middleware is built and the router is enabled; the files under
[`invalid/`](invalid/) are loaded the same way and asserted to be **rejected** with
the expected message. The check currently reports **62/62**.

| File | Options covered | Variants shown |
| :--- | :--- | :--- |
| [`01-core.yaml`](01-core.yaml) | `issuer`, `redirectUrl`, `clientID`, `clientSecret`, `secret`, `scopes`, `pkce`, `loginUrl`, `logoutUrl`, `postLoginRedirectUrl`, `postLogoutRedirectUrl`, `validPostLoginRedirectUris`, `validPostLogoutRedirectUris`, `allowRedirectUriWildcards`, `disableLogin`, `logLevel` | `$ENV_VAR` expansion of the secret; wildcard redirects |
| [`02-issuer-validation.yaml`](02-issuer-validation.yaml) | `trustedIssuer`, `disableIssuerCheck` | a different announced issuer, and the check disabled |
| [`03-discovery-auth-params.yaml`](03-discovery-auth-params.yaml) | `discoveryParams`, `authParams` | extra query parameters for the discovery and the authorization request |
| [`04-claims.yaml`](04-claims.yaml) | `claims` | `Equals`, `Prefix` + `Contains` + `!`, `OneOf` on an access-token role, `SplitContains` + `||` on nested keys with the `id_token.`/`access_token.` prefixes |
| [`05-forwarding.yaml`](05-forwarding.yaml) | `forwardHeaders`, `forwardIDTokenHeader`, `forwardAccessToken`, `usernameClaim`, `identity`, `headers[*].*` | a scalar claim, an array claim (repeated header), a prefixed claim, the templated `headers` extension |
| [`06-client-config.yaml`](06-client-config.yaml) | `clientConfig.timeoutSeconds`, `clientConfig.maxRetries`, `clientConfig.tls.ca`, `clientConfig.tls.cert`, `clientConfig.tls.key`, `clientConfig.tls.insecureSkipVerify` | timeouts/retries, CA by path, mTLS, verification disabled |

| [`09-store-redis-single.yaml`](09-store-redis-single.yaml) | `session.store.redis.endpoints`, `.username`, `.password`, `.database`, `store.keyPrefix` | one endpoint, credentials from the environment, another database |

| [`12-store-tls-paths.yaml`](12-store-tls-paths.yaml) | `session.store.redis.tls.caBundle`, `.cert`, `.key` | file paths (custom CA + mTLS) |
| [`13-store-tls-inline.yaml`](13-store-tls-inline.yaml) | `session.store.redis.tls.{caBundle,cert,key}`, `.insecureSkipVerify` | path variant plus the development mode; the inline-PEM variant is generated by the check from the test PKI (and documented in comments) |
| [`14-csrf.yaml`](14-csrf.yaml) | `csrf.headerName`, `csrf.secure` | header name and HTTPS-only cookie |
| [`15-disable-login.yaml`](15-disable-login.yaml) | `disableLogin` | no login route: unauthenticated requests get a 401 |

> **Gotcha of the file provider.** Traefik renders the configuration of its *file*
> provider as a Go template, so a double-brace expression never reaches the plugin
> (and, in a comment too, it aborts the whole file with
> `function ... not defined`). The templated `headers` extension therefore belongs
> to providers that pass the configuration through untouched (Traefik Hub or
> Kubernetes CRD); with the file provider use literal values, as in
> [`05-forwarding.yaml`](05-forwarding.yaml).
